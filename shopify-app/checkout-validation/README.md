# Native checkout qualification

The county preflight is not installed in Shopify and is not part of the 0.4.6 runtime ZIP. A ZIP list, a storefront warning, or a rule that runs only after an order has been paid does not meet the checkout requirement.

`rules.mjs` is the tested rule core for qualifying a provider; it is not a Shopify Function extension. An adapter must supply the installed app-owned plan IDs, actual Shopify line values and product classification, the authoritative Pacific date, and the selected fulfillment and address from checkout. It must verify each selected delivery group, tie its county proof to that group's current address, and reject proof on address change. Customer-entered cart attributes cannot vouch for county, prices, fulfillment or review of a service week. Preserve fixed bundle and ordinary pickup behavior.

`shopify-input.graphql` describes the documented Function input fields; `shopify-adapter.mjs` exercises that shape locally. The fixture reads actual selected delivery methods, variant IDs and selling-plan IDs, not storefront labels. It fails closed on ambiguous or unsupported delivery methods, mismatched amounts, and discount allocations on restricted lines until live promotion behavior is qualified. Confirm the store's Pacific timezone and the selected option/price fields on mixed and accelerated checkouts. The fixture validates the service week for custom plans and prevents ordinary or fixed-bundle orders from being submitted after Friday's cutoff until Monday, using [Shopify's local date](https://shopify.dev/docs/api/functions/latest/cart-and-checkout-validation#Input.fields.shop.localTime.date). A fresh custom-plan order for the next eligible week can pass during the weekend. Native zones still set the one-time $99 threshold and $15 delivery fee, which must be checked at each applicable charge. Nothing in this directory is installed on Shopify or proves live enforcement.

`delivery-proof.mjs` is the local signing and verification reference. The Ed25519 proof binds the exact normalized street, unit, city, province, country and postal code to Place in Thyme, the Orange County boundary ID, the Pacific date and service week. Only the public verification key belongs in app-owned checkout settings. The private signing key belongs with the trusted issuer and must not be sent to Shopify checkout or included in the ZIP. The token has no plaintext address but is not anonymous; do not copy it to logs or analytics. A verifier that is missing, throws, or sees a changed address does not approve delivery. A production issuer still needs an approved address source and must make its own county decision rather than accept one from the shopper.

`service-proof.mjs` is the local signing and verification reference for custom service weeks. The server-approved proof binds the week, one private reviewed-plan reference, the Shopify selling-plan ID, and the actual recurring variant IDs, quantities and paid unit prices. Shopify documents the [line attributes](https://shopify.dev/docs/api/functions/latest/cart-and-checkout-validation#Input.fields.cart.lines.attribute) and [selling-plan fields](https://shopify.dev/docs/api/functions/latest/cart-and-checkout-validation#Input.fields.cart.lines.sellingPlanAllocation). The rule independently recalculates the next eligible Monday. Editing a date on a stale link or copying proof from a different quote now fails in the fixture; a genuinely new approved quote for the later week passes. No production issuer, key, or cart change has been made.

`portable-qa` bundles a synchronous public-key verifier with no Node, browser, or Web Crypto dependencies and exercises the existing checkout adapter using the same deterministic proof bytes. Run `npm ci --ignore-scripts` and `npm test` in that directory. Tests use only transient key pairs and synthetic carts. The package is not included in the SiteGround runtime ZIP. The bundle was about 24 KB in the local probe, above an editor with a 10 KB code/settings limit. A Node VM pass does not verify performance or feature availability in Javy, on SupaEasy, or in actual Shopify checkout. Test bundle capacity, instruction count, exact input fields, and fail-closed behavior in the candidate vendor before using it. The probe's county check intentionally denies all delivery; it is not an alternative to validating real Orange County addresses.

## County verification

The [Census Bureau TIGERweb BAS 2026 county layer](https://tigerweb.geo.census.gov/arcgis/rest/services/TIGERweb/State_County/MapServer/25) provides the geographic boundary for Orange County, California (GEOID 06059). Run `node shopify-app/checkout-validation/check-public-boundary.mjs` to test the boundary with public locations. A trusted location in the county can pass; an outside point cannot; missing/untrusted coordinates and points within 100 meters of the line are flagged for review. That review margin is a pilot safeguard, not a change to the merchant's delivery area.

The live probe correctly classified both City Halls in ZIP 90631. [La Habra](https://www.lahabraca.gov/557/Contact-City-Hall) is inside; [La Habra Heights](https://www.lhhcity.org/209/Community-Profile) is outside. The public Census address geocoder returned a different, interpolated point for La Habra Heights City Hall, dropping the directional prefix and misclassifying the address. The probe uses the independently [published civic facility point](https://211la.org/agencies/Hx4z89bDXf4ayelNSz6P093u9OWam5/city-of-la-habra-heights), not that interpolation. No shopper data was sent to the Census Bureau or another geocoder.

An offline point lookup would avoid sending each customer's address to a geocoding provider. Orange County publishes [OCFA/OCPW address-point service metadata](https://ocgis.com/arcpub/rest/services/Map_Layers/Address_Point_Final_Planning_Addressing/FeatureServer), but the layer request timed out in this environment and countywide coverage, freshness and permitted reuse were not established. The [USDOT National Address Database](https://www.transportation.gov/mission/open/gis/national-address-database/national-address-database-nad-disclaimer) also warns that coverage varies. Before using either, confirm eligible records across incorporated and unincorporated Orange County, ambiguous addresses near the boundary, and coverage for apartments, new buildings and directional street names. Missing or ambiguous entries require review rather than a positive county approval or a blanket ZIP exclusion. No bulk download or external shopper-address lookup was performed.

November 17 recheck: the county's [download directory](https://pwadmin.oc.gov/service-areas/oc-survey/products/geospatial-data-download) points to a relocated page that returned Access denied. The [OC Public Works open catalog](https://data-ocpw.opendata.arcgis.com/search?q=address%20point) returned building footprints, not an address-point export, for this search. The [current USDOT release metadata](https://data.transportation.gov/dataset/National-Address-Database-NAD-Text-File/fc2s-wawr/about_data) dates its data to September 30, 2026 but does not establish complete Orange County coverage. None of these pages proves a dependable countywide lookup for manually entered addresses. Do not interpret lack of a record as an out-of-county decision or acquire a national file merely to infer coverage.

[Shopify's Admin mailing address](https://shopify.dev/docs/api/admin-graphql/latest/objects/mailingaddress) documents coordinates on contracts, which might support an independent renewal guard after the live field availability and precision are demonstrated. Do not add customer-data scopes or rely on unchecked centroids. This would not prevent a first paid order. The checkout input does not expose those same coordinates, and [checkout validation network requests](https://shopify.dev/docs/api/functions/latest/cart-and-checkout-validation) aren't available to this Basic store. A Basic-compatible provider must prove how it verifies the selected address before payment and how an address change invalidates earlier approval.

## Required acceptance cases

Run the scenarios against a supported public validation app on Basic or an isolated development store before activation. For customer acceptance, use normal and accelerated Shopify checkout where the selected fulfillment method is supported. A fixture is a prerequisite, not evidence of live enforcement.

| Scenario | Expected result |
| --- | --- |
| Meal plan active menu is $98.99; one-time extras or another week's meals make total exceed $99 | Minimum fails; unrelated items do not count |
| Every selected meal week meets $99; unselected dish quantity is zero | Accept eligible service week; do not add unselected dishes |
| Weekly custom juice is $134.98 before adjustment; one-time tea makes cart exceed $134.99 | Block; tea does not count |
| Custom weekly juice meets $134.99 before the 10% adjustment | Accept weekly payment and four-paid-week commitment; no upfront four-week payment |
| Fixed bundle and ordinary one-time pickup | Keep their existing price/terms; don't apply the custom plan minimums or 10% |
| Delivery at $98.99 recurring merchandise plus one-time extras; then exactly $99 recurring | Block first; accept second at $15 per eligible drop-off; pickup stays free |
| Direct checkout opened before Friday cutoff and submitted after midnight Pacific for the same Monday | Block stale service week and return customer to the next eligible dates |
| Ordinary one-time direct checkout opened before cutoff and submitted after it | Verify the same cutoff without relying on the custom-plan service-week field |
| Winter and summer Friday cutoffs, and a weekend returning shopper | Pacific local calendar decides; allow ordering for the next eligible service week |
| 110 E La Habra Boulevard and 1245 N Hacienda Road, both 90631 | Accept eligible Orange County address; reject Los Angeles County address; don't ban the shared ZIP |
| Change address or switch delivery to pickup in checkout | Re-evaluate selected method and address, with no obsolete approval; pickup shows free Monday after 9:00 AM |
| Promotional discount on a restricted cart, including order-level and automatic discounts | Verify the required minimum using actual eligible amounts; don't assume the nominal per-unit or total amount includes all discounts |
| Checkout rules cannot run or a reviewed address cannot be verified | No unvalidated payment for a restricted order |

Shopify's checkout validation applies at initial checkout, not to recurring billing events. Test custom meal A→B→C→A, one weekly juice renewal per paid week, $15 only per local delivery, failed payment/retry, and cancellation separately in the app-owned contract path. The one-time test order #1001 is evidence for the payment gateway and pickup only.

Live no-order checks on November 11: one Intro Pack showed $94.99 every week and free pickup; $94.99 plus $16.50 one-time did not get delivery; two Intro Packs showed $15 for first delivery and each weekly delivery. That two-pack cart also showed the $15 offer on both sides of shared ZIP 90631. The county case failed native acceptance. No recurring payment or consent was submitted.
